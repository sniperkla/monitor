# Mobile Optimization Plan

## Problem
1. **Master Password Modal is laggy on mobile** — uses heavy `Rnd` (react-rnd), `Particles` with infinite animations, blur effects, and complex motion.div animations that kill mobile GPU performance.
2. **Windows auto-maximize on mobile** — user wants free-form (draggable/resizable) windows on mobile so they can see the entire desktop space.

## Changes

### 1. MasterPasswordModal — Mobile-friendly rendering
**File:** `src/components/MasterPasswordModal.js`

- Detect mobile via `useIsMobile()` hook
- On mobile: skip `MacOSModalWindow` (which uses `Rnd`), render a simple **full-screen sheet** instead
- Disable `Particles` component on mobile (return null)
- Simplify motion animations on mobile (no infinite glow/pulse, no blur effects)
- Use `createPortal` directly with a simple overlay + content div

```jsx
// At top of component:
const isMobile = useIsMobile();

// Replace particles on mobile:
function Particles({ count = 30, color = '...' }) {
  const isMobile = useIsMobile();
  if (isMobile) return null;
  // ... existing particle code
}

// At bottom, replace the return:
if (isMobile) {
  return createPortal(
    <AnimatePresence>
      {isOpen && (
        <motion.div className="fixed inset-0 z-[90000] flex items-end sm:items-center ..."
          {/* Simple overlay */}
          <motion.div className="w-full max-h-[90vh] overflow-y-auto bg-[var(--window-bg)] rounded-t-2xl ..."
            {/* Title bar (simplified, no Rnd) */}
            {renderContent()}
          </motion.div>
        </motion.div>
      )}
    </AnimatePresence>,
    document.body
  );
}

// Desktop: keep existing MacOSModalWindow path unchanged
```

### 2. MacOSModalWindow — Skip Rnd on mobile
**File:** `src/components/MacOSModalWindow.js`

- Import `useIsMobile` hook
- When `useFloating` is true AND mobile: render without `Rnd`, use a simple centered/fullscreen container instead
- This benefits ALL modals using MacOSModalWindow (ConnectionModal, etc.)

### 3. Window.js — Enable free-form windows on mobile
**File:** `src/components/Desktop/Window.js`

- **Remove** the auto-maximize: `const isMaximized = _isMaximized || isMobile;` → `const isMaximized = _isMaximized;`
- **Remove** the auto-toggle on mount: delete the `if (window.innerWidth < 768 && !_isMaximized) toggleMaximize(id);` block
- Adjust mobile initial window size to be smaller (e.g., 70% of screen width, 60% height) so multiple windows are visible
- Keep resize handles enabled on mobile (remove `enableResizing={!isMaximized}` → just `enableResizing={true}` when not maximized)
- Touch-friendly resize handles: ensure resize handle touch targets are large enough (min 12px)

### 4. DesktopEnvironment — Smaller default window size on mobile
**File:** `src/components/Desktop/DesktopEnvironment.js`

- When opening a window on mobile, pass smaller `initialWidth`/`initialHeight` (e.g., 70vw × 60vh)
- Offset window positions so stacked windows are visible

### 5. globals.css — Mobile window styles
**File:** `src/app/globals.css`

- Ensure `.window-container` on mobile has `border-radius: 8px` (not 0) for free-form feel
- Add touch-friendly resize handle sizing for mobile

## Files to modify
1. `src/components/MasterPasswordModal.js` — mobile sheet rendering, disable particles
2. `src/components/MacOSModalWindow.js` — skip Rnd on mobile
3. `src/components/Desktop/Window.js` — remove auto-maximize, adjust mobile sizing
4. `src/components/Desktop/DesktopEnvironment.js` — smaller default window size on mobile
5. `src/app/globals.css` — mobile window styling tweaks

## Recommended default
- Mobile window size: **70% width × 60% height** (good balance of usability and desktop visibility)

## Verification
1. Open on mobile device or Chrome DevTools mobile emulator (iPhone/Android)
2. Verify Master Password modal appears as a bottom sheet, scrolls smoothly, no lag
3. Open multiple app windows — they should appear as floating, draggable, resizable windows (not maximized)
4. Drag windows around — should be smooth on touch
5. Resize windows by dragging edges — touch targets should be easy to grab
6. Desktop icons should still be visible in the background
