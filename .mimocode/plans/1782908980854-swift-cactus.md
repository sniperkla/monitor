# Webhook Verification & Readiness Tags for Auto-Deploy

## Overview
Add two features to the Auto Deploy system:
1. **Readiness Tags** -- automatic status badges ("ready", "incomplete", "disabled") on each deploy project based on config completeness
2. **Test Webhook Button** -- sends a test ping to verify webhook endpoint is reachable and properly configured

---

## 1. Readiness Tag System

### Logic (computed client-side, no backend changes needed)
Compute readiness from existing `deployConfig` fields:

| Status | Condition | Color |
|--------|-----------|-------|
| `ready` | `enabled=true` + deploy command set + git provider connected + branch set (+ SSH connection if targetType=ssh) | Green/emerald |
| `incomplete` | `enabled=true` but missing one or more required fields | Amber |
| `disabled` | `enabled=false` | Gray/muted |

Required fields check:
- `enabled === true`
- `deployCommand` is non-empty and not the default placeholder
- Git provider connected: `githubConnected === true` OR `bitbucketConnected === true`
- `branch` is non-empty
- If `targetType === 'ssh'`: `connectionId` is non-empty

- **Project selector dropdown** (around line 2473): Show readiness indicator (colored dot) next to each project name
- Add a small helper function `getReadinessStatus(config)` that returns `{ status, missing[] }`

## 2. Test Webhook Button

### New API Endpoint
**File**: `/Users/katanyoo/Desktop/monitor/src/app/api/deploy/webhook-test/route.js` (new file)

`POST /api/deploy/webhook-test?project=<projectId>`

What it checks:
1. Config exists and is accessible
2. If secret is set, validates HMAC signature generation works (self-test)
3. If git provider is connected, verifies the token is still valid (lightweight GitHub/Bitbucket API call, e.g., `GET /user` or `GET /repos/{owner}/{repo}`)
4. If SSH target, verifies the SSH connection is reachable (quick connect + disconnect)
5. Returns structured result: `{ success, checks: [{ name, status, message }] }`

Each check is independent -- partial success is possible (e.g., webhook reachable but SSH connection down).

Checks:
| Check | What it does |
|-------|-------------|
| `config` | Config exists, enabled, command set |
| `signature` | Secret is configured (if set) |
| `git_provider` | GitHub/Bitbucket token is valid (API call) |
| `ssh_connection` | SSH connection is reachable (connect + immediate disconnect) |

### UI Changes in `SettingsApp.js`
- **New state**: `webhookTesting` (boolean), `webhookTestResult` (object or null)
- **New handler**: `handleTestWebhook()` -- calls `POST /api/deploy/webhook-test?project=<id>`, displays results
- **Button placement**: Next to the Webhook URL field (around line 2907), as a "Test Webhook" button
- **Result display**: Small inline result panel below the button showing each check with pass/fail icons
