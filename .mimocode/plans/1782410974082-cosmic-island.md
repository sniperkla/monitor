# Fix: Commit Selector Fetch Error

## Problem
"Select Commit" button fails with "Failed to fetch" error. Root cause: `apiFetch` doesn't check `res.ok`, so non-200 API responses (400, 500) get passed to `res.json()` which may fail or return unexpected data. Also, when `apiFetch` detects HTML content-type, it throws "Session expired or server error" which gets caught as a generic fetch failure.

## Files to Modify
- `src/apps/SettingsApp.js` — fix `handleFetchCommits` error handling

## Fix
In `handleFetchCommits` (line 475), add `res.ok` check before parsing JSON:

```javascript
const res = await apiFetch(endpoint);
if (!res.ok) {
  const errData = await res.json().catch(() => ({}));
  throw new Error(errData.error || `Server error: ${res.status}`);
}
const data = await res.json();
```

This ensures:
- Non-200 responses show the actual server error message
- JSON parse failures are handled gracefully
- The user sees a meaningful error instead of "Failed to fetch"
