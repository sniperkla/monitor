# Server Backup & Migration App

## Overview
New desktop app for backing up server files, databases, Docker data, and system configs — with download, cross-server transfer, and restore capabilities.

## UI Layout
- **Sidebar**: 4 tabs — Backup, Restore, Transfer, Jobs
- **Backup tab**: Connection picker → type cards (Web App / Docker / Database / System / Custom) → type-specific config → delivery picker (download or transfer) → Start button → log viewer
- **Restore tab**: File upload → target connection → restore path → preview contents → Restore button
- **Transfer tab**: Source (from completed backup) → target server dropdown → target path → Transfer button
- **Jobs tab**: Table of past jobs with status, size, date, actions (download/transfer/delete)

## Backup Types
1. **Web App**: `tar -czf` with user-specified paths + exclude patterns
2. **Docker**: `docker inspect` to find compose dirs + bind mounts, volume tars via alpine container
3. **Database**: `mongodump` / `mysqldump` / `pg_dump` → tar
4. **System**: tar `/etc/ssh`, `/etc/cron.d`, `/etc/systemd`, `/etc/apt`, crontabs
5. **Custom**: user picks paths via SFTP directory browser

## Execution Pattern
- SSH via `ssh2.Client` (same as deploy webhook)
- Background job with `nohup bash -c '...' > /tmp/backup_{id}.log 2>&1 &`
- Progress polled via log file tail, `---FINISHED---` / `---ERROR---` markers
- Same pattern as Docker backup in `server.js:1276`

## Cross-Server Transfer
- **Mode A (direct rsync)**: SSH into target, run rsync from source
- **Mode B (SFTP relay)**: download from source SFTP → upload to target SFTP in chunks

## Restore
- Browser file upload → server buffers to `/tmp` → SFTP upload to target → `tar -xzf -C <path>` for files, db-specific restore commands for dumps
- Preview: `tar -tzf` to show contents before restoring
