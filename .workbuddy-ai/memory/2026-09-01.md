# 2026-09-01

## Diagnosed: Hermes agent model setting falls back to z-ai/glm-5.2 after clean install

User report: model configured as `openrouter/free` (sent as `config.settings.model`), but after
uninstall + reinstall the running Hermes gateway uses `z-ai/glm-5.2`.

Root cause — `src/app/api/agents/hermes/route.js` writes the model three times during `install`:

1. **Step 5** (L1388-1403) — correct. Remaps `model` → `model.default` before
   `hermes config set`. The comment at L1396-1398 already documents the hazard: a bare
   `model` top-level scalar clobbers the nested model block → invalid YAML → fallback to
   `z-ai/glm-5.2`.
2. **Step 5a** (L1410-1431) — the "guaranteed write" Python direct-YAML merge uses the RAW
   key `model`. Its regex `^model:` matches the *block header* and replaces it with
   `model: openrouter/free`, orphaning the indented children → **invalid YAML**.
   Reintroduces exactly the bug step 5 was fixed for.
3. **Step 5b** (L1443-1450) — repairs via `hermes config set model.default ...`, but hermes
   can't parse the now-broken file, and the failure is swallowed by `| tail -1 || true`.
4. Gateway starts (L1452) on an unreadable config → hermes built-in default `z-ai/glm-5.2`.

Identical raw-key merge bug in the `reconfigure` path (L845-866).

### Why the UI still *shows* the right model
Read-back (L682-686) is 3-tier: `hermes config get model` → `grep -E '^model:' config.yaml`
→ `.env MODEL`. Tier 1 fails (broken config) but tier 2 matches the clobbered scalar line and
returns `openrouter/free`. So the Overview lies: it displays the configured model while the
runtime is on glm-5.2.

### Why "clean install" specifically
- Wizard defaults `purge: true` (`HermesAgentWizard.js:73`). Purge does `rm -rf ~/.hermes`
  + all `~/.hermes-*` (L619-621, L630).
- Uninstall backs up **both** `.env` and `config.yaml` (L626), but install restores only
  `.env.bak` (L1343-1377). `config.yaml.bak` is never restored.
- Wizard form deliberately never pre-fills from the server (`HermesAgentWizard.js:146-148`,
  resets at 157-169 / 179-192), so the model must be retyped — and then step 5a corrupts it.

### Secondary findings (other agents)
- ZeroClaw: model written only inside `if prov:` / `if key:` — no provider API key ⇒ no model
  block ⇒ agent default. Read-back greps only top-level `^(model|model_provider|default_model)=`
  so the new `[providers.models.*]` schema never displays.
- Nanobot install writes a provider-less preset and lacks reconfigure's provider backfill.
- No route hardcodes a fallback model; `z-ai/glm-5.2` comes from the hermes binary itself.
