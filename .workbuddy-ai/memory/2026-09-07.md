## WebUI proxy: SPAs stuck on boot splash — root cause + fix

Symptom: nanobot WebUI froze on "Loading nanobot…", Hermes on a blank green
screen (production and dev). Both are Vite/rolldown SPAs.

Diagnosis (reproduced locally with puppeteer-core + local Chrome against
`http://localhost:3030`, session JWT minted via `next-auth/jwt` `encode` from
`.env`, connection `fc-fedora40`):
- Entry HTML + entry chunk served 200, but the three lazy chunks
  (`katex`, `markdown-vendor`, `syntax-highlight`; Hermes: `plugins`,
  `themes`, `chat-activation`, …) came back **400 connectionId required**.
- Those requests had **no query string** and `referer: …/assets/index-*.js?connectionId=..`.
  A bundler resolves relative imports against `import.meta.url`, and **RFC 3986
  relative resolution drops the base URL's query** — so `?connectionId=&port=`
  on the entry module evaporated. Module graph never completes → React never
  mounts → static boot splash forever.
- Verified: nanobot's boot splash is `<div id="root">…Loading nanobot…</div>`
  in its index.html, i.e. a "JS never ran" marker, not an app state.

Fix: tunnel coordinates now live in the **path**.
- `assetPathPrefix()` → `/api/agents/webui-proxy/m/<connectionId>/<port>`.
- `rewriteHtml` rewrites `src|href|action` and CSS `url(/…)` to that prefix
  (no query), so preload URL and dynamic-import URL are byte-identical and
  Chrome dedupes them.
- `[...path]/route.js` reads `m/<cid>/<port>` out of the path; legacy query
  form still accepted (guarded by `hasQueryCoords` + numeric-port test).
- Added `fixSubresource` in the injected head script: rewrites root-absolute
  `src`/`href` set after load (property setters, `setAttribute`,
  `insertAdjacentHTML`, `innerHTML`, plus a MutationObserver net) — needed
  because Hermes' router `pushState`s to `/sessions`, moving the document base
  off the proxy.

Files: `src/app/api/agents/webui-proxy/route.js`,
`src/app/api/agents/webui-proxy/[...path]/route.js`,
new `tests/webui-proxy-assets.test.mjs`. 380 tests pass, eslint clean.

Known residual (not fixed): after Hermes' router escapes to `/sessions`, some
*duplicate* modulepreloads still 404 at `/assets/*.js`. Pages still render
(verified SESSIONS and Achievements). But reloading a URL like
`https://monitor.eaqdragon.com/sessions` cannot work — no coordinates in it.
Also: the URL bar form `/api/agents/webui-proxy#/?bootstrapSecret=…` has no
query (the head script strips it via `replaceState`), so it only works when
opened from the app, never from a bookmark/reload.

Debug recipe that worked: mint a session JWT, set it as
`next-auth.session-token` on `localhost`, drive
`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` via
puppeteer-core, log `pageerror` + `response>=400` + CDP
`Network.requestWillBeSent` initiators.
