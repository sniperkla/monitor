## ROOT CAUSE — production Hermes "green stuck background" (user: prod green, localhost fine)

**Cause: a poisoned browser-cache entry on the `monitor.eaqdragon.com` origin.**
Found by scanning the user's Chrome caches on disk (`~/Library/Caches/Google/Chrome/*/Cache/Cache_Data`):

```
URL:          https://monitor.eaqdragon.com/api/agents/webui-proxy/m/<conn>/9119/assets/index-DY9avcdQ.js
content-type: text/html; charset=utf-8          <-- HTML where JS is required
cache-control: public, max-age=31536000, immutable
cf-cache-status: MISS      (origin response, not Cloudflare)
date:         2026-09-13 05:41:30 GMT  (= 12:41 Bangkok)
```

`index-DY9avcdQ.js` is Hermes' **entry module**. The browser refuses to execute a
module whose MIME is `text/html` ("Failed to load module script"), so the entry
never runs and Hermes' static boot splash stays forever = the green screen.
`immutable` means it is **never revalidated** — a normal reload cannot fix it;
only a hard reload / "clear site data" / a URL change can.

The same URLs cached under `localhost:3030` are **real JS** — which is exactly
why localhost renders the full dashboard. The poison is per-origin.

### Why it came back now

- `4680c2d7` added `?v=<epoch>` to hashed assets **specifically to escape this
  poisoned URL** — and that is the era the user's 19:55 screenshot falls in.
- `8e4f604d` removed the epoch (correctly: a query suffix splits the module
  graph). But removing it also re-pointed the app at the bare poisoned URL.
  So both eras are green, for two different reasons.

### Why `?v=` splits the module graph (measured against the real bundle)

Fetched Hermes from a local `hermes dashboard --skip-build --port 9119` and read
the emitted bundles:

- dynamic import: ``import(`./ConfigPage-X.js`)`` → resolved by the **browser**
  against the **module URL**; RFC 3986 **drops the base query**.
- preload deps: `__vite__mapDeps` returns `"assets/X.js"`, and the helper emits
  `"/" + dep` → **origin-root-absolute**. (This is why `rewriteRootAssetRefs`
  writes `relPrefix` *without* a leading slash.)

Both agree on `/api/agents/webui-proxy/m/<conn>/<port>/assets/X.js` — until a
`?v=` is added, which the preload keeps and the import loses → two module
instances → `SystemActionsProvider` context split → green splash. A **path**
segment survives both rules, a query string survives only one.

### Tooling gotcha (cost real time, general)

**Do NOT batch several edits to the SAME file in one message.** Eight edits to
`MEMORY.md` all reported "Successfully edited", but only **one** survived — each
call reads the file, applies its change and writes, so concurrent writes clobber
each other and the last one wins. Only the line-23 change landed; the size barely
moved, which is what gave it away. Same-file edits must be **sequential**, or
better: rewrite the whole affected block in a **single** atomic edit (that is
what finally worked, and it also makes the diff reviewable in one place).

Corollary: after a batch of edits, verify by re-reading — a "Successfully
edited" result is not proof the change is on disk when writes race.
