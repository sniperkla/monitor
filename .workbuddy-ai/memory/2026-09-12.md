## Evening II: video stuck on loading — ROOT CAUSE WAS THE STALE BUILD + a BROKEN injected script

The user reported: video preview shows, click → stuck loading; prev/next buttons dead. Full investigation:

1. **The installed relay never had the fetch patch.** `public/local-relay.js` had `mpRewrite`/fetch/XHR patches, but `public/local-relay.min.js` was STALE (installed == min.js, both without `__mpFetch`). The fetch to `/media/mp4/?s=` stayed absolute → CORS-blocked → MGP "MP4 failed". Rebuild alone was not enough.

2. **The injected script had a fatal SyntaxError** (`SyntaxError: Invalid regular expression flags`). The mpRewrite scheme test was `/^https?:\\\\/\\\\//i` — 4 backslashes in the relay template literal render to 2 backslashes in the served script → the browser parses `/^https?:\\/` as the regex end → invalid flags → the ENTIRE injected IIFE dies → NO patches apply (fetch, XHR, submit, click-bridge — all dead; previously misdiagnosed as "stale JS"). THIS is what made every site's dynamic media/nav fail. Verified: served HTML's `<script>` failed `node --check` with exactly that; frame reported `fetchPatched:false`.
   **Fix:** rewrote mpRewrite to use a protocol check (`abs.protocol!=='http:'&&...`) and character classes (`/[+]/`,`/[/]/`) — ZERO backslashes → the class of error is impossible now. `node --check` on the served script passes.

3. **The MGP player's flow** (measured live): fetch `/media/mp4/?s=<jwt>` → `200 application/json` list of `{quality, videoUrl: https://ev.ypncdn.com/...mp4?...}` → at play time does `el.src = <absolute CDN url>` → CDN hotlink-check rejects the 127.0.0.1 referer. The CDN is REFERER-gated, not cookie-gated (verified: direct/relay both 200 video/mp4 52.7MB).
   **Fix:** shadowed `HTMLMediaElement.src` + `HTMLSourceElement.src` setters in the injected bridge (route absolute http(s) through `/p/`), plus a best-effort `Location.prototype.href` setter patch for JS `location.href=` navigations (prev/next style).
   **Verified end-to-end:** assign CDN url → rewritten to `/p/<b64(ev.ypncdn.com)>/...vl_720p_1500k_9628173.mp4` → `206 video/mp4` streams → `play()` → `readyState:4`, currentTime advanced 12.1s, duration 536s, no errors.

4. **Danger learned:** node `str.replace('\\\\')` only replaces the FIRST occurrence per call — a line with two 4-backslash runs needs two calls; verified via served-script + `node --check` after every relay source edit, and via `scripts/build-relay.mjs --check` (deterministic artifact vs source-sha256) + `relay-install-audit.mjs` (match yes) before/after every install.

Deployed artifact: min.js source-sha256 `a83b14…` → rebuilt/repinned to `54c3ac89…` (final: `8a38a16d…` artifact, audit match YES), relay restarted 6:01PM, ping pong. Full `npm test` 523/523; w3schools video probe 10/10; Google search probe still "results rendered". ## Night II: Back/Forward buttons dead — fixed by making the PARENT own history outright

User: "when I click previous nothing happened and on next too". Probe (`scratch/history-nav-probe.mjs`) reproduced it in the real app UI and caught something worse: with the old delegate-to-frame design, clicking Back made the **entire app UI vanish** — the cross-origin frame's `history.back()` traversed the JOINT session history (top page went back). Two defects:

1. `handleBack/Forward` delegated to the frame via `commandRelayFrame` postMessage FIRST and returned unconditionally — postMessage never fails, so the parent's `stepHistory` fallback could never run, even when the frame had nothing to traverse.
2. The parent stack was incomplete: `applyPushedRoute` (relay frame's own 'url' reports — relative links through `<base href>`) updated the omnibox but never pushed to the stack, and `navigateAddress` RESET the stack on every typed address (`history: [url]`), so Back could not return to a previously typed address either.

Fix (all in `AgentWebUIBrowserApp.js`):
- `applyPushedRoute` now RECORDS relay frame-native navigations into the tab stack (same truncate-forward + dedupe discipline as navigateTab; display-only kept for non-relay SPA 'push' reports).
- `navigateAddress` PUSHES onto the stack instead of resetting it.
- Back/Forward = `stepHistory(±1)` for ALL web tabs; **`commandRelayFrame` deleted** — no postMessage history/reload commands remain (each is a silent no-op on a dead document, and the traversal variant killed the app).
- `handleReload` for a live relay tab is parent-driven (`frameRef.current.src = activeTab.frameSrc`); dead tabs still go through `recoverRelayTab`; `relay-required` nudges the status refresh.
- The relay's injected `__mpProxyCmd` listener stays (harmless; older app versions still delegate).

Verified in the real app UI: typed google → wikipedia → **Back worked** (frame+omnibox back to google, app intact) → **Forward worked** (to wikipedia); relative `/wiki/` click → **Back worked**. Full suite **525/525**, eslint clean. New pinned test: 'Back/Forward are parent-driven and the stack includes frame-native navigations'; reload-ordering test rewritten for the parent-driven reload.
