## 2026-09-02

### Security audit remediation — 4 findings fixed

Fixed the following issues identified in the external security audit:

1. **Open Redirect (HIGH)** — `src/lib/auth.js` `redirect` callback: hardened
   with try/catch and origin-comparison via `new URL()`. Protocol-relative
   URLs (`//evil.com`) and backslash tricks now rejected. Every non-allowlisted
   URL returns `baseUrl`, never the attacker value.

2. **CSRF bypass on /api/auth/register (MEDIUM)** — Two-layer fix:
   - `src/lib/csrf.js` `CSRF_EXEMPT_PATTERNS`: narrowed from blanket
     `/^\/api\/auth(\/|$)/` to specific NextAuth framework paths only
     (signin, callback, session, signout, csrf, providers). Custom routes
     (register, forgot-password, reset-password, verify-email) are now
     CSRF-protected.
   - `src/proxy.js` matcher: narrowed the negative-lookahead from `api/auth`
     to `api/auth/signin|callback|session|signout|csrf|providers`. The broad
     exclusion previously meant custom auth routes bypassed the middleware
     entirely (no CSRF check, no CSP header).

3. **Email enumeration on /api/auth/register (LOW)** — Route now returns
   identical 200 response body for new and existing emails. Removed `userId`
   and `email` from response (client only checks `data.success`). Verified
   client code (`RevealScreen.js` L518-532) doesn't use these fields.

4. **CSP localhost wildcard (INFO)** — `src/proxy.js` `buildCsp()`: replaced
   `http://127.0.0.1:*` / `http://localhost:*` wildcard ports with fixed
   port 48923 (relay discovery port). Non-default relay ports now require
   explicit opt-in via `CSP_LOCAL_RELAY` env var.

Findings 5 (no SSRF on /api/health — url param ignored) and 6 (GraphQL
protected) confirmed safe, no changes needed.

All modified files pass `npx eslint` with zero errors/warnings.

### Security audit remediation — Round 2 (defence-in-depth hardening)

1. **OAuth callbackUrl allowlist validation** — Three-layer defence:
   - `src/lib/auth.js`: Added `getCallbackAllowlist()` helper that builds an
     origin allowlist from NEXTAUTH_URL, AUTH_URL, and CALLBACK_URL_ALLOWLIST
     env var. Exported `sanitizeCallbackUrl()` for use by the route handler.
     The `redirect` callback now checks both baseUrl origin AND the explicit
     allowlist.
   - `src/app/api/auth/[...nextauth]/route.js`: Added
     `sanitizeSigninCallbackUrl()` — intercepts GET requests to the signin
     page and replaces external/malformed `callbackUrl` with `/` BEFORE
     NextAuth renders the form. Prevents the attacker value from being
     embedded in the hidden input.
   - Client (`RevealScreen.js`) always uses `callbackUrl: '/'` — no client
     change needed.

2. **CSP localhost removal** — Removed all `http://localhost:*`,
   `ws://127.0.0.1:*`, `ws://localhost:*`, `wss://127.0.0.1:*`,
   `wss://localhost:*` from `connect-src`. The browser only makes a
   fetch to `http://127.0.0.1:48923` (relay discovery). The relay's
   WebSocket runs in the Node relay process, not the browser, so
   ws://localhost was never needed. Non-default ports opt-in via
   CSP_LOCAL_RELAY env var.

### Security audit remediation — Round 3 (clean validation errors + prod CSP)

1. **OAuth callbackUrl — 400 instead of 500** — The previous approach
   rewrote the request URL with `new Request(url, ...)` which produced
   a plain Request instead of a NextRequest, causing NextAuth to 500.
   Rewrote `validateCallbackUrl()` in `[...nextauth]/route.js` to
   return HTTP 400 with a clear error message for invalid callbackUrl
   values. No request mutation — the original NextRequest passes
   through to NextAuth untouched. Validation runs on both GET (form
   rendering) and POST (form submission).

2. **CSP localhost — dev-only** — `http://127.0.0.1:48923` in
   `connect-src` is now excluded from production builds unless
   `CSP_ALLOW_LOCAL_RELAY=1` is set. In dev it's always included so
   relay auto-detection works. Verified client code (AppContext.js,
   SettingsApp.js) gracefully handles the blocked fetch via catch.
